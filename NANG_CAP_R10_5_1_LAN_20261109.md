# AMORRI STUDIO — BẢN NÂNG CẤP GỘP R10.5 (09/11/2026)

**Mục tiêu:** xử lý các lỗi/điểm yếu đã rà soát trong *một release source*, không phải nhiều bản vá nối tiếp. Đây là **source sẵn sàng đưa vào quy trình kiểm thử và phát hành**, KHÔNG phải xác nhận website production đã cập nhật.

## Đã sửa trong source

1. **Nhận diện release** (`app/api/health/route.ts`, `vps/scripts/deploy-web.sh`): `/api/health` hiển thị `amorri-r10.5-batch-20261109`, backend thật (PostgreSQL/Firebase; VPS S3/R2), và SHA Git commit nếu được deploy qua script chuẩn. Marker trên đĩa chỉ được tạo từ SHA commit của `origin/main`, không lấy từ request; không lộ secret.
2. **Chẩn đoán quản trị** (`lib/domain/system-health.ts`, `app/api/system/diagnostics/route.ts`, `components/SystemHealth.tsx`): dùng kiểm tra PostgreSQL bridge / local auth / kho S3 khi chạy VPS, không còn báo giả thiếu Firebase. Chỉ đọc dữ liệu và chỉ Admin có quyền xem.
3. **Bảo vệ login** (`app/api/auth/local/login/route.ts`, `vps/nginx/amorri.conf`): đọc JSON có giới hạn *thực tế* 4 KB kể cả không có Content-Length, vẫn giữ giới hạn 8 lần/5 phút trong Node và bổ sung rate-limit chung cho Nginx (6 request/phút/IP, burst 6) sau khi cập nhật cấu hình Nginx đang chạy. Phân biệt DB bridge ngừng hoạt động (503) với token không hợp lệ (401).
4. **Concept** (`components/ConceptPhotos.tsx`, API Concept): tự làm mới URL ảnh được ký khi hết hạn, chặn metadata có đường dẫn ảnh không khớp ID, thông báo cấu hình VPS S3 đúng ngữ cảnh. Không sao chép/ghi lại 14 ảnh cũ.
5. **Backup off-VPS** (`vps/scripts/backup-vps.sh`): tạo `pg_dump -Fc`, kiểm tra archive, upload ra remote ngoài VPS cùng hai bucket `amorri-video` và `amorri-concept`, đối chiếu danh sách/dung lượng và chỉ tạo marker `COMPLETE.txt` sau cùng. Có `--dry-run`, chặn chạy chồng, không xóa dữ liệu. Bổ sung unit/timer systemd để **có thể cấu hình** backup tự động mỗi ngày; mặc định không kích hoạt.
6. **Thông báo lỗi phù hợp VPS** tại Dashboard, lịch, nhân sự, lookup sự kiện và System Health; tránh hướng người dùng đi sửa Firebase khi đã chuyển sang PostgreSQL.
7. **Kiểm thử:** thêm test regression R10.5, cập nhật assertion release cũ và kiểm thử trình duyệt (Chromium desktop/mobile) vào GitHub Actions khi code được push lên repo.

## Chưa thể hoàn tất khi chỉ có source ZIP

- **Chưa deploy hoặc thay đổi production.** Cần kiểm tra `origin/main`, bản đang active và có backup khả dụng trước khi triển khai.
- **Chưa xác minh end-to-end 14 ảnh Concept.** Phải mở trên trang thật, upload/xóa một ảnh test và kiểm tra URL S3 trả HTTP 200. Không chạy lại tool khôi phục 14 ảnh.
- **Test Node đã đạt 360/360** trên source R10.5 sau khi dùng TypeScript CLI có sẵn (5.8.3) và loại bỏ thư mục `@types` do một lần cài npm thất bại; kiểm tra tĩnh và cú pháp những file TypeScript sửa đổi cũng đạt. Tuy nhiên **chưa cài đầy đủ dependencies từ lockfile**, chưa chứng minh được `next build`, `tsc` project, Vitest hay Playwright E2E đạt trên bản source này. **Bắt buộc** chạy `npm ci`, `npm run typecheck`, `npm test`, `npm run test:unit`, `npm run build`, `npm run test:e2e` trên CI/máy có dependencies đầy đủ.
- **Không thể tự thu hồi khóa Firebase từng bị lộ.** Owner phải xoay vòng khóa đúng thứ tự trong cửa sổ bảo trì với backup và xác minh Drive/Firebase; tuyệt đối không gửi khóa cho ChatGPT hay ghi vào GitHub.
- **Desktop Google OAuth / EXE / DMG, Google Places 403, tài khoản staff và link cũ** cần môi trường thật / quyền thực; không nên tuyên bố đã hoàn thành.
- File này không chứa `.git`, `node_modules`, dữ liệu khách hàng, secrets hoặc tệp backup production.

## Cách áp dụng một bản cập nhật duy nhất (Windows + GitHub + VPS)

**1. Trên Windows**, giải nén gói ZIP mới, lấy thư mục `SOURCE/AmorriStudio_R10_5_FULL_SOURCE.zip` (hoặc patch `PATCH/R10_4_to_R10_5.patch`). Mở terminal tại **repository GitHub hiện có**, không tạo repo mới đè `main`:

```powershell
git status --short
git fetch origin main
git pull --ff-only origin main
# Đặt đường dẫn đến PATCH thực tế sau khi giải nén gói:
git apply --check "C:\DUONG_DAN\R10_4_to_R10_5.patch"
# Chỉ sau khi check sạch và đã xem git diff:
git apply "C:\DUONG_DAN\R10_4_to_R10_5.patch"
git diff --stat
npm ci
npm run typecheck
npm test
npm run test:unit
npm run build
```

Nếu `git status` đã có sửa đổi, `git pull`/`git apply --check` báo xung đột, hoặc mã mới trên main khác snapshot R10.4: **dừng, so sánh từng thay đổi**, không `git reset --hard`, không ghi đè toàn bộ source. Khi các test đạt, mới `git add`, commit, push như một PR/release duy nhất. Không push `prod.env`, OAuth keys, service-account JSON, data dump.

**2. VPS, trước khi chuyển release:** xác minh symlink hiện tại, chụp snapshot backup dữ liệu. Cấu hình sẵn *remote ngoài VPS* của `rclone` và remote đọc S3, thử dry-run bằng:

```bash
sudo AMORRI_BACKUP_REMOTE=offsite:amorri-backups AMORRI_BACKUP_SOURCE_REMOTE=local-s3 \
  bash /opt/amorri/scripts/backup-vps.sh --dry-run
sudo AMORRI_BACKUP_REMOTE=offsite:amorri-backups AMORRI_BACKUP_SOURCE_REMOTE=local-s3 \
  bash /opt/amorri/scripts/backup-vps.sh
```

Đây là **ví dụ**: `offsite` phải thực sự trỏ tới dịch vụ độc lập với VPS, `local-s3` phải khớp rclone remote S3 hiện có (có máy dùng tên `local`). Script mới phải được copy vào `/opt/amorri/scripts/` trước khi chạy. Trước khi tin vào backup, khôi phục thử `postgres.dump` trong **môi trường staging độc lập**, kiểm tra ảnh/video. Tuyệt đối không restore đè vào DB production để thử.

**3. Build candidate trên VPS**, sau khi commit R10.5 được push lên GitHub main:

```bash
sudo -u amorri bash /var/www/amorri/repo/vps/scripts/deploy-web.sh
# Script sẽ in BUILT_RELEASE=<đường dẫn> và COMMIT=<SHA>.
# Phải xác nhận đây là R10.5 và tất cả test/build đều thành công trước khi promote.
```

**4. Chuyển đúng một release** sau khi đủ điều kiện. Lưu đường dẫn cũ từ `readlink -f /var/www/amorri/current`, liên kết symlink `current` sang `BUILT_RELEASE` theo bước in từ `deploy-web.sh`, restart `amorri-web`, chạy `vps/scripts/verify-r105-release.sh`. Nếu health fail, khôi phục symlink cũ, restart dịch vụ, điều tra nguyên nhân. Không thực hiện lại import Firebase/PostgreSQL.

**5. Nginx:** không thay thế nguyên file HTTPS đã được Certbot chỉnh! Chỉ merge `limit_req_zone` ở `http` context và `location = /api/auth/local/login` từ file mẫu `vps/nginx/amorri.conf` vào cấu hình đang dùng; chạy `sudo nginx -t` trước khi reload, giữ nguyên TLS/redirect hiện hành. Sau khi rate limit hoạt động, kiểm tra login đúng/sai không bị khóa oan.

**6. Backup hằng ngày (sau khi đã kiểm tra 1 lần thực tế):** copy `vps/systemd/amorri-backup.{service,timer}` vào `/etc/systemd/system/`, tạo `/etc/amorri/backup.env` bảo mật (mode 0600) chứa `AMORRI_BACKUP_REMOTE=...` và `AMORRI_BACKUP_SOURCE_REMOTE=...` (không chứa S3 secret), sau đó `systemctl daemon-reload`, `systemctl enable --now amorri-backup.timer`. Giám sát timer và dung lượng remote; lập chính sách retention và test restore định kỳ.
